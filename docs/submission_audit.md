# Аудит подачи по кейсу «Умный город» — 30.09.2026

Это перечень проверяемых фактов и открытых рисков, а не самооценка в баллах жюри. Источник требований — предоставленный организаторами PDF кейса, страницы 7 и 9–15.

## Допуск и обязательный комплект

| Требование | Факт / статус |
|---|---|
| Основной сценарий в MAX | Бот REAL в личном и групповом чате, mini-app запускается из MAX. Групповой приём сообщения и голос live-проверены; общая карточка создана и отредактирована через настоящий MAX API. Полный проход новой карточки с сообщением жителя после деплоя и визуальный осмотр остаются. |
| Исходники зафиксированы | Git commit и source ZIP с SHA-256 готовятся после последнего изменения; сам ZIP должен быть реально приложен к заявке. Приватная ссылка на GitHub без доступа не подходит. |
| Docker / README / зависимости | Compose, Dockerfile, `.dockerignore`, `.env.example`, lockfile и README есть. Чистая сборка и миграции ранее проверены; повторить после финального коммита. |
| PDF, первый технический слайд | Есть ссылка на бота, mini-app, API, имя архива/версия/SHA и шаги. После изменения кода обновить хеши и приложить архив. Рабочий токен нельзя публиковать в открытом репозитории; если организаторы требуют его, передавать в закрытом канале подачи и затем ротировать. |
| Собственный API | HTTPS, OpenAPI и `DATA-API.yaml` есть. Публичное чтение доступно; запись требует подписанного MAX initData или внутреннего bot-key. Проверяющему нужен MAX-доступ или отдельный согласованный тестовый сценарий для write API. |

## Продуктовая часть: 40% онлайн-оценки

| Критерий | Подтверждено | Что снижает уверенность |
|---|---|---|
| Масштабирование (35% продуктовой части) | Один core обслуживает House A/B с разными объектами, УК, маршрутами и порогами. | Нет self-service подключения новой УК; нужны проверка каталога домов, ответственные и официальные процессы. |
| Пользовательская ценность (25%) | Житель видит проблему и результат; объект сохраняет историю повторов. | Нет интервью с реальными жителями/УК и измеренного эффекта пилота. Цифры эффекта — только гипотезы. |
| UX/UI (20%) | Ролевые очереди, русские статусы, ошибки и пустые состояния; чат + mini-app. | Полный сценарий нужно пройти на MAX mobile и web с разными аккаунтами. |
| Целостность (15%) | Все действия связаны с Issue/Asset и единым состоянием в БД. | Передача в УК пока симулируется и должна называться учебной на каждом шаге. |
| Презентация (5%) | PDF с проблемой, сценарием, архитектурой, ML-ограничениями и пилотом. | Добавить наблюдения пользователей, если команда их реально соберёт; не подменять их выдуманными числами. |

## Техническая часть: 60% онлайн-оценки

| Критерий | Подтверждено | Остаточный риск |
|---|---|---|
| Функции (30%) | Закрытый цикл, reopen, инициатива, второй дом; 20 повторных E2E; MAX принял создание и редактирование групповой карточки. | Полный многоаккаунтный проход новой карточки после деплоя. |
| Интеграции (20%) | Настоящий MAX Bot API, группа с `read_all_messages`, Bridge-login, групповой callback опроса. | Нет официального API УК/ГИС; Submission `is_simulated=true`. |
| Стабильность (10%) | Идемпотентность, повторные тесты, retry, работа после ошибок, локальный clean Compose. | VPS с высокой CPU steal может давать задержки; нужна запасная площадка/репетиция. |
| Архитектура (20%) | Домен и явные состояния отдельно от MAX adapter, AI и интерфейса. | Состояние групповых карточек хранится в bot volume; для нескольких воркеров нужен общий стор и единственный потребитель polling. |
| Безопасность (10%) | Секреты не в Git, MAX initData, роли в API, ограничение фото, provenance. | `BOT_ROLE_MODE=showcase` разрешает самовыбор роли ради жюри. До доступа реальных жителей — allowlists + `assigned`, привязка к дому и политика хранения фото. |
| Документация (10%) | README, demo runbook, OpenAPI, DATA-API, evidence registry. | Финальные артефакты должны ссылаться на один commit и быть реально доступны проверяющему. |

Платформенный бонус возможен, если жюри самостоятельно пройдёт полный сценарий в MAX и увидит ценность групповой карточки, callback-подтверждения, персональных действий и мини-приложения. Наличие API и количества экранов само по себе бонус не даёт.

## Обязательные действия команды до отправки

1. Приложить окончательный source ZIP и PDF, проверить совпадение SHA-256 и commit hash; приватный репозиторий не выдавать за общедоступный.
2. Получить настоящие MAX `user_id` участников через `/мой_id` и закрепить роли; до этого режим показа раскрывать как ограничение.
3. Пройти сценарий на мобильном и веб-MAX четырьмя аккаунтами, записать экран и проверить групповой чат после последнего деплоя.
4. Передать необходимые рабочие токены только через закрытый канал организаторов, если без них нельзя проверить заявленный режим. После подачи ротировать ранее раскрытые ключи.
5. Собрать хотя бы несколько реальных наблюдений о боли и не превращать гипотезу пилота в «измеренный эффект».
